# Learning System

## Design philosophy

The website applies established learning-practice ideas to the UGC NET workflow rather than treating study as passive reading.

The intended cycle is:

**Understand → Retrieve → Apply → Practice → Space → Master**

## Understand

The learner first forms a usable representation of the concept. Content is layered so the learner can start with the essential idea and expand when needed.

## Retrieve

The learner attempts to reconstruct information from memory. This creates a stronger test of learning than simply rereading.

## Apply

The learner uses the concept in a scenario, comparison or explanation. Application checks whether the concept can be used rather than merely recognised.

## Practice

MCQs and PYQs provide exam-oriented retrieval and discrimination practice. Errors should feed back into learning and revision.

## Space

The learner returns after a delay rather than repeatedly rereading in one sitting. Revision ratings determine when the next return is useful.

## Master

Mastery is an evidence state, not a page-completion state. The intended evidence chain is:

**Understand + Retrieve + Apply + Retain**

## Important product rule

Do not duplicate the same information merely because it is available in multiple content layers. Repeat information only when the repetition serves a different learner decision—for example:

- learning the concept;
- recalling it;
- distinguishing it in an exam;
- applying it;
- deciding when to revise.

## Future state model

The agreed next architecture introduces a canonical learner state:

**User action → event → reducer → canonical learner state → mastery/revision**

This is PLANNED. The current application must be treated as the source of truth until that migration is implemented and validated.
