# Micro-topic lesson authoring template

Copy this template into the content-preparation packet for each new or substantially rewritten micro-topic. It is an editorial checklist, not a demand to create the same length of lesson for every concept.

## Identity and placement
- **Canonical ID:** `unit-topic-micro`
- **Unit → topic → micro-topic:**
- **Learning objective:** After studying, the learner can…
- **Chunk rationale:** Why this is a coherent concept or skill that can be learned and retrieved together.
- **Prerequisites / links:** Only concepts genuinely needed to understand it.

## Understand — learner explanation
- **Core explanation:** Define and explain the concept in accurate, learner-friendly language.
- **Mechanism / components:** Include only what the concept requires.
- **Example:** A concrete example that makes the concept distinguishable.
- **Boundary:** What this concept does not mean.

## Expand — depth and distinctions
- **Important distinctions:** Contrast with the closest commonly confused concept(s).
- **Relationships:** Show how the idea connects to its parent topic and unit.
- **Misconceptions:** Explain why a tempting wrong interpretation is wrong.
- **Exam cue:** A useful recognition cue, not a replacement for understanding.

## Apply — practice
- **Authentic PYQ connection:** Include only if the exact source question is verified. Record exam/year/source/page where available; preserve stem, option order and correct answer.
- **Why it maps here:** Explain the concept tested and any prerequisite concepts.
- **Generated practice item:** Label it as generated practice, never as a PYQ.
- **Answer rationale:** Explain the correct choice and why the closest distractor is wrong.

## Final quality gate
- [ ] It is a natural learning chunk, not an arbitrary subdivision.
- [ ] A learner can explain the concept without reading the next micro-topic.
- [ ] It has a clear relationship to the parent topic and unit.
- [ ] Examples, recall prompts and practice test the same learning objective.
- [ ] No unsupported facts or invented PYQ metadata.
- [ ] No duplicate explanation unless it serves a different learning decision.
- [ ] Existing canonical ID is preserved unless an approved structural change requires otherwise.
